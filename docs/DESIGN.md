## 1. 为什么现在乱

### 1.1 工作方式

- **没有规格就动手。** 10-03 首页一天提交了 12 次以上：三件事竖列、四格条、四栏卡、样张条、关于段，轮流加了又删。每轮都是看一眼截图凭感觉改，没有一份文字能说清「这一页要什么」。
- **人拍过的事没有记下来。** 10-02 冯说过首页「不要四格统计、不要大样张、8 行真字货架」（集群记忆 #9024），10-03 的几轮又把四格统计、关于段加了回去。决定散在会话和记忆里，下一个 agent 看不到。
- **在活页上试。** `HANDOFF.md` 的规矩是「先出两份整页，选定，精修，再接线」，首页这几轮直接改 `/`。
- **几个 agent 同时改一个仓。** 同一天 Gemini 和 wapuu 都在改首页，互相覆盖。
- **自评就算过。** 改完自己截图说「对齐了」，没有可以量的标准。

### 1.2 审美

- **主角错了。** 这是字体站，页面上最有表现力的应该是字体本身。现在最大的元素是 2–4 个字的巨型标题（源文件、索引、去上游、授权证明），每页都一样大，没有一个是字体。
- **每页都是同一个公式。** 都是「巨标题 + 右侧导语 + 横线 + 左列表 / 右卷宗」，所以页与页之间分不出性格，读着像同一张表单反复出现。
- **标题说的不是这一页的主体。** 一款字体的详情页，h1 是「去上游」（一个动作），字体名反而降到二级。
- **网格不严。** 列表行向左外扩 16px；目录的状态列每行 x 坐标都不一样；两栏比例有 1.2:0.9，也有 0.9:1.2；检索框前有时挂「检索」两个字、有时没有。
- **内部词上了页面。** 卷宗、这一站、三态结论、textState……访客看不懂。
- **CSS 失控。** `site.css` 2972 行，二十多套页面前缀（`hv4-` `lq5b-` `fd1-` `gp1-` `ab6-`……），基础组件每页重写一次。37 处字号写死、12 处颜色写死。

**结论**：先立规范，再一页一页按规范改；每一步都能对照条文验收。

## 2. 平台：做什么、给谁、不做什么

### 2.1 一句话

**wenfeng.org（文风开源）是开源字体的源文件和许可原文站：能拿的直接拿，不能拿的告诉你去哪拿；标准开源协议可以出具授权证明。**

对仗：店面「文风字体」`app.windfonts.com` 负责网页里用（托管 CSS、账号、选字、样张）。文风开源负责带走（原件、原文、证明、切片包）。

### 2.2 来访的人和他们要办的事

| 谁 | 从哪来 | 要办的事 | 落点 |
|----|--------|----------|------|
| 前端 / 建站的人 | 店面 CSS 里的嵌入注释 `wenfeng.org/license` | 确认这款字能不能商用、能不能嵌入 | `/license/{norm}/` |
| 设计师、WP 站长 | 搜索、店面、口碑 | 拿到源文件，或本地用的切片包 | `/source/{norm}/` → 下载 / 去出处 / 切片 |
| 企业法务、采购、招投标 | 被要求出具合规材料 | 一份中文、可核验、有责任主体的授权证明 | `/attest/` → 证书 → `/v/` 查验 |
| 字体作者、知情人 | 发现信息有误、字没收录 | 纠错、报缺 | `/gap/` |
| 程序 | API | 读目录和许可字段 | `/api/v1/fonts` |

### 2.3 功能地图

| 功能 | 页面 | 现状 |
|------|------|------|
| 目录检索、按状态筛 | `/source/` | 有，分页 20 |
| 一款字体档案 | `/source/{norm}/` | 有，需按 §8 重排 |
| 许可原文总入口（**路径已冻，店面注释写死**） | `/license/` | 有 |
| 单款许可原文 | `/license/{norm}/` | 有 |
| 厂商分组 | `/foundry/`、`/foundry/{slug}/` | 有 |
| 授权证明：出证、证书、核对 JSON、台账、两要素查验 | `/attest/` 及其子页、`/v/` | 有，新版 |
| 切片包（禁再分发款，核验原包后领取） | `/slice/`、`/slice/{norm}/` | 有 |
| 报缺字 / 缺收录 / 勘误 | `/gap/` | 有，**提交未接** |
| 说明：怎么核、用法、法务、关于 | `/how/` `/use/` `/legal/` `/about/` | 有 |

### 2.4 不做

- 不当店面：没有选字袋、账号、控制台、整库 webfont 预览、样张墙。
- 不当 CDN：不托管网页字体 CSS。
- 不给厂商自拟协议出证（普惠体、仓耳、HarmonyOS、MiSans、OPPO 等），只给原文。
- 不托管禁再分发的原件，只列条目、给出处、给切片门。
- 不放造字编辑器（独立新域，本站只做入口和收录）。
- 不搞钓鱼维权，不收割用户。

### 2.5 字体状态（全站唯一的一套）

| 状态词 | 含义 | 主动作 | 字段 |
|--------|------|--------|------|
| 本站下载 | 源文件在本站 | 下载 | `offer=source` |
| 官方下载 | 本站不留文件，去作者或厂商的发布处 | 去出处 | `offer=jump` |
| 暂无下载 | 许可已核实，源文件包还没上架 | 看条目 | `offer=pending` 且 `textState=full` |
| 待核实 | 许可原文还没有核对记录 | 看条目 | `offer=pending` 且 `textState≠full` |
| 未收录 | 镜像还没收到这款 | 报缺 | `offer=missing` |

规则：
- 状态词、动作词全站同词同形。不另造近义词（「可带走」「去上游」等旧词逐步换掉）。
- 是否「可出证」是另一个维度（`can_attest`），不混进这五态。

## 3. 气质

### 3.1 三个词

**克制 · 准确 · 有证据**

- **克制**：白底、灰阶、留白。界面不抢字体的戏。一页只讲一件事。
- **准确**：每个结论都对应数据字段。不说大话，不写「最全」「权威」。待核实就写待核实。
- **有证据**：结论旁边就是出处，包括原文链接、核实日期、哈希。证据用等宽小字排成一层，不藏起来，也不放大。

### 3.2 一个比喻

**一座小而好的字体档案馆的卡片目录。** 卡片排得整齐，字体本身就是展品，管理员话少但每句都对。

### 3.3 参照与反例

| 参照（学它的哪一点） | 反例（别学） |
|----------------------|--------------|
| Google Fonts 单款页：字体名用本字体排，信息分层清楚 | 数据大屏：一排大数字 |
| Fontsource：工程感，字段和文件一目了然 | SaaS 落地页：渐变、大插图、三栏卖点卡 |
| Apple 官网：简约、中文排得舒服、按钮只有一套（冯的偏好） | 字体下载站：广告位、密表、标签云 |
| 出版社书目页：书名是主角，版权页信息有固定位置 | 2–4 字巨型标题每页都摆一遍 |

### 3.4 落到界面上的五条

1. **字体是主角。** 字体名尽量用该字体真字排（见 §7.6）。UI 本身一律用普惠体，灰阶，不跟字体抢。
2. **一页一个主问题。** 第一屏只回答一个问题（§8 每个模板都写明这个问题是什么）。
3. **标题说主体。** 档案页的 h1 是字体名，不是动作。工具页的 h1 是工具名。
4. **安静的层级。** 层级靠字号、字重、灰度、留白来分。不靠框、底色、阴影。
5. **证据层固定。** 日期、哈希、字段、路径一律等宽小字，放在固定位置。

## 4. 信息架构

### 4.1 顶栏导航（建议改，待拍板 §13-1）

现在是：`源文件（=首页） / 授权 / 目录 / 核验 / 关于`。「源文件」指首页，又和「目录」意思重叠，访客分不清。

建议：**字标 = 首页**；导航为 `目录 / 授权 / 核验 / 用法 / 关于`。

| 导航 | 落点 | 高亮范围 |
|------|------|----------|
| 字标「文风 · 开源」 | `/` | 首页 |
| 目录 | `/source/` | `/source/*` `/foundry/*` |
| 授权 | `/license/` | `/license/*` |
| 核验 | `/attest/` | `/attest/*` `/v/` `/slice/*` |
| 用法 | `/use/` | `/use/` `/how/` |
| 关于 | `/about/` | `/about/` `/legal/` `/gap/` |

右侧：`店面`（外链 `app.windfonts.com`）、深浅切换。设计/开发切换不放顶栏，用 `?view=dev`（已上线）。

### 4.2 页脚

保持现在的三列（办事 / 核验 / 关于）加品牌句。品牌句不改：「源文件、许可原文、缺字反馈。开源字体直接下载，其余核验或去出处。不做样张墙，不当 CDN。」

### 4.3 URL

全部冻结，不改路径。`/license` 和 `/license/{norm}` 被店面嵌入注释引用，**永远不能改**。

## 5. 体验原则与关键路径

### 5.1 原则

1. **三秒知道能不能拿。** 任何出现字体的地方都同时给出状态词和主动作。
2. **每页都有下一步。** 页尾必须有去处，不许出现死路。待核实、未收录的页面尤其要有。
3. **不承诺做不到的事。** 按钮写「去出处」就真的跳出去。提交没接上就写明「这一下不会送出」。
4. **离站要说。** 站外链接一律新窗口，并带 ↗ 标记（「即将离开文风」确认层见记忆 #8648，另起任务）。
5. **少一步就少一步。** 检索回车直达目录并带上关键词。筛选写进 URL（`?st=` `?q=` `?page=`），可分享，刷新不丢。

### 5.2 关键路径（每条都要在验收时走一遍）

| 路 | 步骤 | 终点 |
|----|------|------|
| A 拿开源原件 | 首页检索「霞鹜」→ 目录行 → 档案页 → 下载 / 去出处 | 拿到文件或到达上游仓库 |
| B 从嵌入注释查许可 | `/license/` → 搜名 → 单款原文 | 读到原文和结论 |
| C 出授权证明 | 首页或导航「核验」→ `/attest/` 选字、填单位 → 证书 → 下载 PDF | 拿到 PDF，编号可在 `/v/` 查到 |
| D 禁再分发款 | 档案页（如普惠体）→ 去厂商官网取原包 → `/slice/{norm}/` 上传核验 → 领切片包 | 拿到切片包 |
| E 纠错 / 报缺 | 任意档案页「信息有误」或目录空结果「报缺收录」→ `/gap/` | 看到表单和「这一下不会送出」 |

## 6. 文案规范

### 6.1 语气

- 短句，先说结论。像档案馆管理员：话少，每句都准。
- 不用营销词：最全、权威、一站式、赋能、极致。
- 不用内部词：卷宗、这一站、三态、收源、进仓、桶、端口、textState、offer（这些只出现在开发视图）。
- 不用 emoji，不用感叹号。
- 固定句交付前念一遍，念不顺就改（COPY-AUDIT 第七轮的规矩）。

### 6.2 词表（同一概念只用一个词）

| 用 | 不用 |
|----|------|
| 字体 | 字（指一款字体时）、字库 |
| 源文件、原件 | 原文件、这份源、源 |
| 许可原文 | 授权文本、许可证文 |
| 授权证明（产品名），证书（指那一份） | 核验证书、证、凭证（混用时） |
| 切片包 | 样张包、分片 |
| 派生 | 衍生 |
| 厂商 | 组织、收源 |
| 官方下载 / 去出处 | 去上游、跳转、外链 |
| 字体名用原名（「霞鹜文楷」） | 「文风·霞鹜文楷」（**只**在证书证面上用） |

### 6.3 双视图

- 设计视图（默认）：讲人话。
- 开发视图（`?view=dev`）：只露路径、字段、API，例如 `/source · offer=source`。
- 写法：`<span class="for-design">…</span><span class="for-dev mono">…</span>`。一处有设计文案，就必须有开发文案。

## 7. UI 规范

> 只用 `site/assets/tokens.css` 里的变量。禁止在 CSS 里写颜色值和字号数字（tokens.css 本身除外）。

### 7.1 网格

| 项 | 值 |
|----|----|
| 内容最大宽 | `--container`，**建议从 96rem 收到 80rem**（1280px，待拍板 §13-2）。现在 1440 以上的屏幕行太长，不舒服 |
| 侧距 | `--gutter`（24px），≤720 宽为 16px |
| 列 | 12 列，列距 24px |
| 标准两栏 | 主栏 8 列 + 侧栏 4 列，中间空 1 列（约等于现在的 `.split.is-wide`）。**全站只用这一种两栏** |
| 落地页页头 | 7 + 5 |
| 阅读宽 | 正文段落最宽 38em |
| 左边缘 | 所有文字的左边缘落在容器左线上。hover 底色可以外扩 `--s-3`，文字不动 |

### 7.2 字阶（按用途命名，落到现有 token 上）

UI 字体：`--font-ui`（普惠体）。只用两种字重：400、700。

| 用途 | 字号 | 字重 | 行高 | 用在哪 |
|------|------|------|------|--------|
| 落地标题 | `clamp(2.5rem, 5vw, 3.5rem)` | 700 | 1.1 | 只在首页 |
| 页标题 h1 | `--fs-40` | 700 | 1.15 | 目录、授权、核验、说明类页 |
| 字体名标题 | `clamp(2.5rem, 6vw, 4rem)`，**用该字体真字** | 400 | 1.1 | 档案页 h1 |
| 区块标题 h2 | `--fs-22` | 700 | 1.3 | |
| 小标题 h3 | `--fs-16` | 700 | 1.4 | |
| 导语 | `--fs-16` | 400 | 1.7 | `--ink-2` |
| 正文 | `--fs-14`（长文 `--fs-16`） | 400 | 1.7 | |
| 列表字体名 | `--fs-22`，真字 | 400 | 1.2 | 字体行 |
| 辅助 / 说明 | `--fs-13` | 400 | 1.5 | `--gray` |
| 标签 / 眉题 | `--fs-12` | 400 | 1.4 | `--gray`，字距 .04em |
| 证据层（日期、哈希、字段、路径） | `--fs-12` | 400 | 1.4 | `--font-mono`，`--gray-2` |

**废止**：每页 5.75rem 的 2–4 字巨型标题（丁式大字）。大字只留给首页落地标题和档案页的字体名。

### 7.3 颜色

- 只用灰阶：`--page --surface --fill --surface-2 --rule --ink --ink-2 --gray --gray-2`。
- 墨黑实底（`--ink`）**一屏最多一处**，给这一屏的主动作。
- 不用红色。只有真故障（核对失败、查无此证）可以用 `--ink` 加图标表达，不加色块。
- 不用投影、渐变、暖纸色（证书证面除外，它是独立的印刷品版式）。
- 深色模式由 token 自动切换，组件里不写深色特例。

### 7.4 间距与节奏（只用三档）

| 层级 | 落地页 | 其他页 |
|------|--------|--------|
| 区块之间 | `--s-24`（96px） | `--s-16`（64px） |
| 区块内组与组之间 | `--s-10`（40px） | `--s-10` |
| 组内 | `--s-3` 到 `--s-6` | 同左 |

- 一页里的横向分隔线最多 2 条（列表行线、表格行线不算）。
- 页头下面不再画横线。用留白隔开。

### 7.5 组件（全站只有这些，新增要先改本节）

| 组件 | 类名 | 规格 | 禁止 |
|------|------|------|------|
| 顶栏 | `.topbar` | 高 `--topbar-h`；字标左；导航胶囊，当前项 `--fill` 底 | 加第三层菜单 |
| 面包屑 | `.crumb` | mono 12，`--gray-2`；首页不显示 | 用来当标题 |
| 页头 | `.pagehead` | 眉题（可选）+ h1 + 导语；导语跟在 h1 下面，不再挤到右栏 | 右侧放大段导语 |
| 检索 | `.search` | 高 3rem，`--fill` 胶囊；按钮嵌在框内右侧；不挂「检索」标签（用 `sr-only` label） | 框外再放灰按钮 |
| 筛选 | `.seg`（单选分段）／`.chips` | 状态筛用 `.seg`；当前项 `--ink` 底 | 一排超过 6 个 |
| 按钮 | `.btn` `.btn-ink` `.btn-text` | 高 2.25rem，胶囊；文字 13；图标 0.95rem | 第四种按钮样式 |
| **字体行** | `.frow` | 见 §7.6，全站目录、首页货架、厂商页、出证列表共用 | 各页自己写行样式 |
| 键值表 | `.kv` | 左键 5.5em `--gray`，右值 `--ink`；行线 `--rule` | 套卡片底色 |
| 侧注 | `.aside` | 左竖线 1px `--rule`（不再用 `--ink` 黑线），内边距 `--s-6` | 一页两个以上 |
| 入口列表 | `.links` | 标题 16/700 + 说明 13 `--gray` + 箭头；一行一个；hover `--fill` | 墨黑整行 |
| 表单 | `.form` | 标签在上，输入框 `--fill` 胶囊，高 2.75rem | 浮动标签 |
| 结果条 | `.result` | 图标 + 一句结论 + 详情 KV；成功、失败只靠图标和措辞区分 | 红绿色块 |
| 代码块 | `.code` | mono 13，`--surface` 底，圆角 `--radius-sm` | 语法高亮配色 |
| 分页 | `.pager` | 安静数字，当前页 `--ink` 700；±2 窗口 | 胶囊色块 |
| 空状态 | `.empty` | 一句话 + 一个去处 | 插图 |
| 证据行 | `.evidence` | mono 12 `--gray-2`，用 `·` 分隔 | 加粗、加色 |

### 7.6 字体行 `.frow`（核心组件）

```
| 霞鹜文楷（真字 22）        | OFL-1.1 · LXGW          | 本站下载 |   下载 → |
|  minmax(0,1.4fr)           |  minmax(0,1fr) 13 gray  |  6rem    |   5rem   |
```

- **固定四列**，状态列和动作列每行 x 对齐（修现在每行乱跳的问题）。
- 行高 56px。行线 `--rule`。hover 底色 `--fill`，外扩 `--s-3`。
- 状态词 12 号 `--gray`；动作词 13 号，「下载」用 `--ink` 700，其余 `--ink-2`。
- 开发视图：第二列换成 `norm · offer=… · textState=…`。
- ≤720 宽：只留字体名和动作，信息列收到字体名下面一行。

**真字规则**（来自 #9024，并守住「不当 CDN、不整库加载」）：
- 只给**可视区内**的行加载真字（IntersectionObserver，已有 `lazyPreviews()`）。
- 来源只用 `cn.windfonts.com` 的 CSS API，`subset=zh-common`。
- 先用 UI 字体占位，行高固定，切换时不跳行。加载失败就留在 UI 字体。
- 一页最多加载 20 款（等于分页数）。首页最多 8 款。

### 7.7 图标

- Remix Icon 线性，24 网格，现有 sprite（`assets/icons.svg`）。
- 尺寸只有 0.95rem（按钮内）和 1.05rem（入口圆标）。
- 不用 emoji，不混用其他图标集。

### 7.8 动效

- 只有 hover 和 focus：底色、颜色、箭头位移 4px。时长 `--dur`，缓动 `--ease`。
- 不做入场动画、视差、骨架闪烁。

### 7.9 响应式

| 断点 | 规则 |
|------|------|
| ≤ 960 | 两栏变单栏，侧注排到主栏后面 |
| ≤ 720 | 侧距 16px；顶栏导航可横向滚动；字体行两列 |
| 全部 | 任何宽度都不能横向滚动 |

### 7.10 可访问性

- 对比度：正文 `--ink-2` 以上；`--gray-2` 只用于证据层和占位。
- 所有交互件都有可见 focus（2px `--ink` 外框，偏移 2px）。
- 图标按钮有 `aria-label`；检索有 `sr-only` label。

## 10. 工作方法

### 10.1 角色

| 角色 | 谁 | 负责 |
|------|----|------|
| 拍板 | 冯 | 选稿、批规范变更 |
| 协调 | 一个主 agent | 写本页规格、审稿、提交、更新 `DECISIONS.md` |
| 执行 | 一个执行 agent | 按规格打字、跑验收脚本、回报 URL |

**一个仓同一时间只允许一个执行 agent。** 开工 `session-claim.sh claim`，收工 `release`。派工前跑 `~/Projects/linuxjoy/scripts/mac/pre-dispatch-check.sh`。

### 10.2 一页的生命周期

```
① 规格  →  ② 两份整页稿（/lab/）  →  ③ 冯选  →  ④ 精修 ′  →  ⑤ 接入活页  →  ⑥ 验收  →  ⑦ 记账
```

1. **规格**：协调者对照本文写出这一页的规格（第一屏问题、骨架、组件、文案、数据），写在 `docs/pages/<page>.md`。
2. **两份整页稿**：做在 `/lab/<page>-a/` 和 `/lab/<page>-b/`，完整顶栏、页脚、深色、开发视图、移动端都要有。**活页不动。**
3. **冯选**：只发两个链接，不发截图（冯 10-03 原话：自己看）。
4. **精修**：只改选中那一版。要加区块或换结构，就退回第 2 步重出整页稿。
5. **接入**：替换活页函数，删除落选稿和这一页的旧前缀 CSS。
6. **验收**：跑 §12 的清单，全部通过才提交。
7. **记账**：在 `DECISIONS.md` 追加一条（日期、页面、选了哪版、否了什么、冯的原话）。

### 10.3 纪律

- 一次提交只做一件事。提交信息写清页面和版本，末尾带 agent 签名。
- 活页一天最多变一次结构。
- 不顺手改别的页。看到别页的问题，记进 `docs/pages/<page>.md` 的「待办」。
- 不凭截图自评通过，以 §12 的脚本结果为准。
- 回报格式只有三段：**链接 / 改了什么 / 要冯拍的一件事**。

## 11. 工程规范

### 11.1 目录（逐步迁移，不一次大搬）

```
site/
  build.py              入口：load → 渲染 → 写 dist
  lib/
    data.py             load、status、can_attest、lic、spdx_of、计数
    ui.py               组件函数：pagehead、search、seg、frow、kv、aside、links、result、pager
    layout.py           layout（顶栏、页脚）
  pages/
    home.py  source.py  font.py  license.py  attest.py  docs.py  tools.py
  assets/
    tokens.css          唯一的变量来源
    base.css            reset、排版基线
    components.css      §7.5 组件，每个组件一段
    templates.css       §8 六类模板骨架
    pages/*.css         页面特例，每页 ≤ 40 行，类名 .pg-<page>-*
    site.js
```

### 11.2 CSS 规则

- 颜色、字号、间距、圆角只能写 `var(--…)`。
- 新增类名只能在 `components.css`（组件）或 `pages/<page>.css`（特例）里。不再新增 `hv4-` 这类版本前缀。
- 每接入一页，删掉这一页的旧前缀规则。目标：`site.css` 拆完后总行数 ≤ 1200（证书 `.cert-*` 另计）。
- `t-{norm}` 前缀留给真字字体类，模板类用 `tpl-`，避免冲突。

### 11.3 检查脚本 `site/check.py`（第一个要建的东西）

| 检查 | 方法 |
|------|------|
| 构建 | `python3 site/build.py` 成功，页数不少于基线 |
| 写死值 | 在 `assets/*.css`（不含 tokens.css）里 grep 十六进制颜色和 `font-size: 数字` → 必须 0 |
| 横向溢出 | 无头 Chrome，宽度 1440 / 1280 / 1024 / 768 / 390，`scrollWidth - clientWidth == 0` |
| 左边缘 | 1280 宽，`main` 内首层文字块的 `left` 都等于容器左线 |
| 链接 | 页面上所有站内 href 请求本地服务，全部 200 |
| 双视图 | `?view=dev` 下没有空的 `.for-dev` |
| 深色 | `wf-theme=dark` 下没有 `--page` 以外的白底块 |

脚本输出一张通过 / 失败表。执行 agent 把这张表贴进回报。
